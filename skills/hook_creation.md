**Hook Creation Skill \- Portable**

*V2 \- portable framework with channel format and content intent separated*

# **Purpose**

Generate consistent, high-quality hooks across multiple content channels. This is a portable, first-principles skill. It carries no brand, industry, or project assumptions. Apply brand voice, audience context, offer details, and the active channel list on top of this framework.

# **Core Principle**

A hook is a short, customer-facing line that does two things:

1\.	Catches attention by naming a situation, cost, decision, or useful contradiction.

2\.	Clearly implies a payoff for reading, opening, clicking, or taking the next step.

Both are required. A hook that grabs attention without implying a payoff creates curiosity with no direction. A hook that promises a payoff without catching attention gets ignored.

# **Pain-Forward Bias**

Most hook packages should lean pain-forward because people respond strongly to avoiding loss, friction, mistakes, or wasted effort. That does not mean every hook should be negative.

* Pain-forward: Problem Recognition, Cost of Wrong Choice, Contrarian Correction  
* Outcome-forward: Practical Outcome, Identity Match  
* Contextual support: Curiosity Gap, Local Reality / Contextual Specificity

Aim for roughly 60-70% pain-forward hooks in a full package. Use outcome-forward hooks for contrast and variety. Avoid a full package of nothing but pain because it becomes repetitive and can feel manipulative.

# **Tension Drivers**

| Driver | Use |
| :---- | :---- |
| Problem Recognition | Shows the reader a problem, friction, or decision they may already be experiencing. |
| Cost of Wrong Choice | Shows what goes wrong when the reader chooses poorly, delays, or assumes incorrectly. |
| Curiosity Gap | Creates a useful unanswered question without becoming clickbait. |
| Contrarian Correction | Challenges a common assumption or reframes an accepted belief. |
| Local Reality / Contextual Specificity | Uses location, season, industry, role, conditions, or environment when context affects the decision. |
| Identity Match | Calls out the reader's type, role, situation, or self-image so they recognize themselves. |
| Practical Outcome | Points toward a useful, concrete result the reader wants. |

# **Hook Source Priority**

When generating hooks, draw from the richest available context first:

1\.	Actual content being promoted, such as blog, email body, landing page, video script, or offer copy

2\.	Author/operator firsthand experience or expertise

3\.	Customer problem, job-to-be-done, or decision point

4\.	Product, service, offer, or subject matter involved

5\.	Local, seasonal, role-based, or situational specificity

6\.	Topic description alone, which is the weakest source and should be used only when nothing richer is available

# **Hook Structure Bias**

Favor these grammatical structures:

* Statements \- primary default. Declarative, confident, direct.  
* Commands \- secondary. Direct instruction or guidance.

Default patterns:

* Statement: \[Problem / Cost / Contrarian truth\] that implies a payoff  
* Command: Do / Don't / Before you X, Y that implies a payoff

Questions, lists, exclamations, conditionals, and story openings are allowed but should not dominate any channel or package. Regardless of structure, every hook must follow the core principle: attention plus implied payoff in one line.

# **Tension Driver Fit by Channel Format and Content Intent**

Do not treat channel and intent as the same thing.

* Channel format defines the constraint: subject line, preview text, image overlay, caption, business profile post, etc.  
* Content intent defines the job: educate, build brand memory, generate a lead, or drive a click.

Select both before generating hooks. Example: channel \= social\_caption, content\_intent \= lead\_generation. The rankings below are starting defaults. Calibrate them with performance data over time.

## **Channel Format Defaults**

### **Email Subject Lines**

The reader decides in seconds whether to open. The subject line must create clear tension without needing the preview text to make sense.

| Rank | Driver | Rationale |
| :---- | :---- | :---- |
| 1 | Problem Recognition | Reader recognizes the situation from their own experience. |
| 2 | Cost of Wrong Choice | Strong for readers still in decision mode. |
| 3 | Curiosity Gap | Useful when grounded and practical, not clever for its own sake. |
| 4 | Contrarian Correction | Good occasionally, but overuse can erode trust. |
| 5 | Practical Outcome | Often better suited for preview text. |
| 6 | Local Reality / Contextual Specificity | Usually stronger in preview text where there is room to ground it. |
| 7 | Identity Match | Usually stronger in preview text or body copy. |

### **Email Preview Text**

Preview text serves the subject line. It deepens the tension without resolving it. Subject line and preview text must use different tension drivers.

| Subject Line Driver | Preview Text Driver Options | Rationale |
| :---- | :---- | :---- |
| Problem Recognition | Practical Outcome or Local Reality / Contextual Specificity | Grounds the problem in something tangible. |
| Cost of Wrong Choice | Problem Recognition or Local Reality / Contextual Specificity | Makes the cost feel real and specific. |
| Curiosity Gap | Practical Outcome or Identity Match | Gives enough specificity to confirm the email is worth opening. |
| Contrarian Correction | Practical Outcome | Shows the correction leads somewhere useful. |

Preview text rules:

* Must not resolve the subject line's tension  
* Must not introduce unrelated tension  
* Must add specificity or stakes without giving away the answer

### **Image Overlay Hooks**

Primary scroll-stopper. Use 3-7 words, one idea, and tension appropriate to the post intent.

| Rank | Driver | Rationale |
| :---- | :---- | :---- |
| 1 | Contrarian Correction | Compresses well and challenges assumptions quickly. |
| 2 | Curiosity Gap | Creates an open loop when the rest of the post resolves it. |
| 3 | Practical Outcome | Works well when the post delivers advice directly. |
| 4 | Cost of Wrong Choice | Adds stakes in few words. |
| 5 | Problem Recognition | Works when worded sharply. |
| 6 | Identity Match | Can use too many words at this length. |
| 7 | Local Reality / Contextual Specificity | Use only when context is the tension. |

### **Social Caption Hooks**

The visual usually stops the scroll. The caption hook either earns the read-through, drives the click, or moves the reader toward action.

| Rank | Driver | Rationale |
| :---- | :---- | :---- |
| 1 | Problem Recognition | Grounds the post in the reader’s real situation. |
| 2 | Cost of Wrong Choice | Deepens stakes after the visual catches attention. |
| 3 | Practical Outcome | Signals the post will be useful. |
| 4 | Identity Match | Confirms relevance for the right reader. |
| 5 | Contrarian Correction | Useful when the post challenges a bad assumption. |
| 6 | Curiosity Gap | Use carefully; withholding can feel mismatched when the post itself should answer. |
| 7 | Local Reality / Contextual Specificity | Usually stronger in body copy unless context is the main hook. |

### **Local Search / Business Profile Posts**

Readers are already searching for a business, category, product, or service. They do not need to be stopped mid-scroll. They need confidence that they are in the right place.

| Rank | Driver | Rationale |
| :---- | :---- | :---- |
| 1 | Problem Recognition | Meets the reader where they already are. |
| 2 | Practical Outcome | Signals the business can help them get the result they searched for. |
| 3 | Identity Match | Confirms they are the right type of customer. |
| 4 | Local Reality / Contextual Specificity | Strong when location, season, or conditions matter. |
| 5 | Cost of Wrong Choice | Adds stakes to a decision they are already making. |
| 6 | Contrarian Correction | Use lightly; decision-mode readers usually want reassurance. |
| 7 | Curiosity Gap | Weakest here; searchers usually want answers, not open loops. |

## **Content Intent Defaults**

Use these intent defaults to adjust the channel defaults. Keep the final hook shaped by both the channel format and the post objective.

### **Advisory / Educational Content**

The payoff is in the content itself. The hook should earn attention while signaling practical help.

| Rank | Driver | Rationale |
| :---- | :---- | :---- |
| 1 | Problem Recognition | Names what the reader is dealing with. |
| 2 | Practical Outcome | Shows the content will help them do something better. |
| 3 | Identity Match | Confirms the advice is for their situation. |
| 4 | Cost of Wrong Choice | Useful but can feel heavy if overused. |
| 5 | Contrarian Correction | Good when correcting a common mistake. |
| 6 | Local Reality / Contextual Specificity | Useful when context changes the advice. |
| 7 | Curiosity Gap | Use sparingly because advisory content should not feel like withholding. |

### **Brand Awareness Content**

The goal is memory, trust, familiarity, and positioning. The hook should make the right audience understand what the brand stands for without pushing too hard for immediate action.

| Rank | Driver | Rationale |
| :---- | :---- | :---- |
| 1 | Identity Match | Helps the right audience recognize that the brand understands people like them. |
| 2 | Local Reality / Contextual Specificity | Makes the brand feel grounded, real, and relevant. |
| 3 | Practical Outcome | Connects the brand to a useful result without sounding overly sales-driven. |
| 4 | Problem Recognition | Shows the brand understands the customer’s world. |
| 5 | Contrarian Correction | Useful occasionally for positioning, but too much can feel argumentative. |
| 6 | Cost of Wrong Choice | Can work, but may feel too sales-driven for awareness. |
| 7 | Curiosity Gap | Usually weaker because brand awareness should clarify, not withhold. |

### **Lead Generation Content**

The goal is to move the reader toward a clear next step: call, message, request a quote, check availability, book, schedule, or ask for help. Hooks should reduce friction and make action feel relevant now.

| Rank | Driver | Rationale |
| :---- | :---- | :---- |
| 1 | Problem Recognition | The reader must identify the need before acting. |
| 2 | Cost of Wrong Choice | Strong for readers close to a buying, booking, or decision point. |
| 3 | Practical Outcome | Shows what action helps them accomplish. |
| 4 | Identity Match | Qualifies the right audience. |
| 5 | Local Reality / Contextual Specificity | Useful when timing, area, season, or conditions matter. |
| 6 | Contrarian Correction | Useful if correcting a bad assumption before the call to action. |
| 7 | Curiosity Gap | Usually weaker because lead generation should reduce uncertainty, not create mystery. |

### **Link / Click-Through Content**

The goal is to make the click feel worth it. The hook should create unresolved but useful tension that the linked content resolves.

| Rank | Driver | Rationale |
| :---- | :---- | :---- |
| 1 | Cost of Wrong Choice | Creates stakes before the reader clicks. |
| 2 | Curiosity Gap | Creates a practical open loop. |
| 3 | Problem Recognition | Connects the click to the reader’s situation. |
| 4 | Contrarian Correction | Useful when the linked content challenges an assumption. |
| 5 | Identity Match | Helps the right reader self-select. |
| 6 | Local Reality / Contextual Specificity | Useful when context makes the click more relevant. |
| 7 | Practical Outcome | Use carefully because it can reveal too much and reduce the need to click. |

# **Channel Pairing Rules**

Elements that work together must complement, not repeat, compete, or resolve each other’s tension.

* Image overlay \= creates initial pull  
* Caption hook \= deepens the tension, earns the read-through, drives the click, or moves toward action  
* Subject line \= creates initial pull in the inbox  
* Preview text \= deepens tension and moves the reader toward opening  
* Subject line and preview text must use different tension drivers  
* For lead generation, the final body copy must include a clear next step; the hook should prepare for the action, not replace it

# **Banned Hook Styles**

Reject hooks that rely on:

* Hype or fake urgency  
* Fearmongering  
* Secret or hidden-knowledge framing  
* Guaranteed results  
* Cheapest-price positioning  
* Corporate buzzwords  
* Unsafe simplification of complex tasks  
* Overpromising  
* Claims not supported by the actual content being promoted

# **Banned or Restricted Phrases**

Avoid these phrases unless directly quoted or contextually required:

* game changer, secret, hack, crush it, dominate, skyrocket, unlock, revolutionize, insane, massive results, guaranteed, cheapest, easy money, effortless, no-brainer, ultimate guide, must-read, you won’t believe  
* top-quality, best-in-class, industry-leading, one-stop shop, solutions, next level, premium service without proof, fast and easy

# **Quality Scoring Rubric**

Score each candidate hook from 1 to 5 in each category.

| Category | Scoring Guide |
| :---- | :---- |
| Clarity | 5 \= instantly understandable; 3 \= understandable but slightly vague; 1 \= confusing or too clever |
| Tension | 5 \= strong reason to keep reading with a concrete implied payoff; 3 \= mild interest; 1 \= flat or informational only |
| Brand Fit | 5 \= matches defined voice and positioning; 3 \= acceptable but generic; 1 \= off-brand |
| Content Fit | 5 \= clearly supported by actual content and context; 3 \= related but not specific; 1 \= unsupported |
| Channel Fit | 5 \= strong fit for format and reader behavior; 3 \= usable but not ideal; 1 \= wrong format |
| Intent Fit | 5 \= strongly serves the post objective; 3 \= partially serves it; 1 \= works against the objective |
| Specificity | 5 \= tied to a real situation, product, condition, audience, or decision; 3 \= somewhat specific; 1 \= generic |
| Trust/Safety | 5 \= responsible, accurate, no overpromising; 3 \= acceptable but should be checked; 1 \= risky or misleading |

# **Minimum Quality Threshold**

Because Intent Fit has been added, the maximum score is now 40 instead of 35\. A hook may be returned only if:

* Total score is 32 or higher out of 40  
* No individual score is below 3  
* Trust/Safety score is 5  
* Brand Fit score is at least 4  
* Content Fit score is at least 4  
* Intent Fit score is at least 4

If a hook fails, reject it. Do not force a fixed number of hooks when quality is weak. Return only hooks that meet the threshold.

# **Tiebreaker Hierarchy**

1\.	Tension \- pick the hook with stronger pull first

2\.	Specificity \- then favor the hook tied to a real situation or condition

3\.	Intent Fit \- then favor the hook that best serves the content objective

4\.	Channel Fit \- then favor the hook best suited to the channel format

5\.	Tension driver diversity \- then favor the hook that adds a driver not yet represented

# **Candidate Diversity Requirements**

## **Within a Single Channel**

* No more than 2 final hooks may use the same tension driver  
* The raw candidate pool must use at least 3 different tension drivers before scoring begins

## **Across the Full Package**

* At least 4 of the 7 tension drivers should be represented across all channels combined  
* The majority should use pain-forward framing, with outcome-forward hooks used for contrast and variety

# **Internal Generation Process**

For each channel and content intent combination:

1\.	Confirm the channel format and content intent.

2\.	Generate 15 to 25 rough candidates using at least 3 different tension drivers.

3\.	Remove anything that violates banned phrases or banned styles.

4\.	Score each candidate using the rubric.

5\.	Keep only candidates that meet the minimum quality threshold.

6\.	Remove duplicates and near-duplicates.

7\.	Apply the tiebreaker hierarchy to select the strongest final hooks.

8\.	Mark the single strongest hook per channel as recommended: true.

9\.	Verify no more than 2 final hooks use the same tension driver.

10\.	If fewer than 3 hooks pass for a channel, flag the issue in quality notes.

After all channels are complete, verify that at least 4 of the 7 tension drivers are represented across the full package when the package is large enough for that diversity rule to be reasonable.

# **Required Output Quantity**

Return 3 to 5 hooks per channel. Each channel array must contain exactly one hook with recommended: true. If fewer than 3 hooks pass the minimum quality threshold for any channel, return only the passing hooks and explain why in quality notes.

# **Input Quality Check**

Before generating hooks, evaluate the available firsthand experience or expertise inputs for substance. An input is thin if it lacks all three of the following:

1\.	A specific customer, user, reader, or situation

2\.	A concrete detail about conditions, behavior, or outcome

3\.	An opinion or lesson that comes from doing the work

When inputs are thin:

* Note which inputs were thin and that hooks are less specific because of it  
* Cap the Content Fit rubric score at 3 for all hooks in the package  
* Require stronger scores in the remaining dimensions to pass the threshold

# **Mandatory Inputs**

The hook generator must receive:

* Topic or content being promoted  
* Actual content, such as blog, email body, landing page, post body, video script, or offer copy  
* Target product, service, offer, or subject  
* Target audience  
* Customer problem, job situation, reader need, or decision point  
* Desired reader action  
* Channel format  
* Content intent: advisory / educational, brand awareness, lead generation, or link / click-through  
* Firsthand experience or expertise context when available  
* Geographic, seasonal, role-based, or situational context when relevant

If the actual content is missing, do not generate final hooks. Return:

INSUFFICIENT\_INPUT: Hook generation requires the actual content being promoted.

# **Output Format**

Return structured JSON. Every hook includes its rubric score, tension driver, channel, and content intent. Exactly one hook per channel is marked recommended: true. Adapt the channel keys to match the active channel list.

{  
  "topic\_id": "{{TOPIC\_ID}}",  
  "hooks": {  
    "{{channel\_key}}": \[  
      {  
        "hook\_text": "\<hook text\>",  
        "channel\_format": "\<channel format\>",  
        "content\_intent": "\<content intent\>",  
        "tension\_driver": "\<driver name\>",  
        "score": 0,  
        "recommended": false  
      }  
    \]  
  },  
  "rejected\_patterns": \[  
    "\<brief description of rejected pattern and reason\>"  
  \],  
  "quality\_notes": {  
    "tension\_driver\_distribution": "\<summary\>",  
    "thin\_inputs": \["\<list of flagged thin inputs, or empty\>"\],  
    "experience\_coverage": "\<strong | adequate | thin\>",  
    "flags": \["\<any quality concerns\>"\]  
  }  
}  
For email channels, use this hook structure instead:

{  
  "subject": "\<subject line text\>",  
  "preview": "\<preview text\>",  
  "channel\_format": "email",  
  "content\_intent": "\<content intent\>",  
  "subject\_tension\_driver": "\<driver name\>",  
  "preview\_tension\_driver": "\<driver name\>",  
  "score": 0,  
  "recommended": false  
}  
Downstream selection logic: for each channel, use the hook with recommended: true. If no recommended flag is found, fall back to the hook with the highest score. If scores are tied, take the first listed. Log a warning whenever the fallback path is used.
